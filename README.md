# invoiq

A LangChain-powered pipeline for querying PDF documents via RAG and extracting structured JSON data from invoices using Google Gemini.

## What it does

**invoiq** handles two distinct workflows over PDF documents:

1. **RAG pipeline** — ask natural language questions about a document and get answers grounded in its content
2. **Structured extraction** — parse an invoice PDF into a typed Pydantic model (invoice number, date, total, line items)

## Tech stack

- [LangChain](https://python.langchain.com/) — orchestration and LCEL chains
- [Google Gemini 2.5 Flash](https://ai.google.dev/) — LLM for answering and extraction
- [HuggingFace `all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) — local embeddings (no API key needed)
- `InMemoryVectorStore` — lightweight in-memory vector store, no external DB required
- `PydanticOutputParser` — enforces typed structured output

## Setup

**1. Clone the repo**
```bash
git clone https://github.com/yourusername/invoiq.git
cd invoiq
```

**2. Install dependencies**
```bash
pip install -r requirements.txt
```

**3. Set up environment variables**

Create a `.env` file in the project root:
```
GOOGLE_API_KEY=your_google_api_key_here
```

Get your key from [Google AI Studio](https://aistudio.google.com/).

**4. Add your PDF**

Place your invoice PDF in the project root and update `file_path` in `invoice_rag.py`:
```python
file_path = "./your_invoice.pdf"
```

## Usage

```bash
python invoice_rag.py
```

This runs both pipelines in sequence and prints:

- The RAG answer to the sample question ("Which products were bought in March?")
- The structured `Invoice` object with all extracted fields

### Customise the RAG query

Edit the query string in `invoice_rag.py`:
```python
rag_result = rag_chain.invoke("What is the shipping address?")
```

### Customise the extraction schema

Modify the Pydantic models to match your invoice format:
```python
class Item(BaseModel):
    description: str
    price: float

class Invoice(BaseModel):
    invoice_number: str
    date: str
    total_amount: float
    items: List[Item]
```

## How it works

### RAG pipeline

```
PDF → PyPDFLoader → RecursiveCharacterTextSplitter
    → HuggingFace embeddings → InMemoryVectorStore
    → retriever (top-k=3) → rag_prompt → Gemini → answer
```

The retriever finds the most relevant chunks for a given query. The RAG prompt instructs the model to answer only from that context, reducing hallucination.

### Extraction pipeline

```
PDF → PyPDFLoader → full page text
    → extraction_prompt + format_instructions → Gemini → PydanticOutputParser → Invoice
```

The full page text (not chunked) is sent to Gemini with format instructions generated by `PydanticOutputParser`. The model returns JSON which is validated and parsed into the `Invoice` object.

## Example output

```
=== RAG Answer ===
In March 2012, Newell 330 (Art/Office Supplies, item OFF-AR-5309) was purchased — 3 units at $17.94 each.

=== Extracted Invoice (structured) ===
Invoice #: 36259
Date:      Mar 06 2012
Total:     $58.11
  - Newell 330 (Art, Office Supplies): $53.82
```

## Limitations

- Uses `InMemoryVectorStore` — not persisted between runs. For large document sets, swap in Chroma or FAISS.
- Designed for single-page invoices. Multi-page extraction may need chunked extraction logic.
- Embeddings run locally on CPU; first run downloads the model (~90MB).
